# 文档校验脚本

`scripts/validate_docs.py` 只读取文档，输出文件路径、行号、规则及问题，不改文件、不创建目录、不联网。使用 Python 3.9 或以上版本，无需安装依赖。

## 调用方法

从 skill 根目录执行，其他工作目录使用脚本的绝对路径。路径含空格时加引号。

检查 PRD 草稿：

```bash
python3 scripts/validate_docs.py --prd /项目文档/PRD.md
```

同时检查技术方案草稿，可用 `--version` 核对预期版本：

```bash
python3 scripts/validate_docs.py --prd /项目文档/PRD.md --plan /项目文档/v1.1/技术方案.md --version v1.1
```

正式归档后检查 PRD、文档清单以及清单各版本的主技术方案：

```bash
python3 scripts/validate_docs.py --prd /项目文档/PRD.md --stage archived --index /项目文档/项目文档清单.md
```

草稿检查不要求版本目录或文档清单已归档。草稿若只在对话中，先在系统临时目录保存待检查文件；按最终相对位置摆放 PRD、方案和所需引用文件，再运行脚本。临时文件不算正式归档，检查后清理。

## 参数校验

| 参数 | 校验规则 |
| --- | --- |
| `--prd` | 必填；存在、可读、UTF-8 编码的 `.md` 文件 |
| `--plan` | 可选；同样检查文件类型和可读性；归档模式下必须指向最新版本的 `技术方案.md` |
| `--index` | 仅与 `--stage archived` 一起使用；文件与 PRD 同级 |
| `--version` | 可选；格式为 `v1.0`、`v1.1` 等，不接受负数、前导零或路径字符串；与最新修改记录比较 |
| `--stage` | 仅接受 `draft` 或 `archived`，默认 `draft` |

各角色不能指向同一文件。不接受未知参数或参数名缩写。文档中的“目标版本”可能是产品版本，不当作文档版本；文档版本以修改记录为准。

## 检查内容

- PRD：必需章节、可选章节的相对顺序、元信息非空、修改记录表头、版本连续性、修改日期有效性、摘要编号，以及正文版本标注是否有对应历史记录。历史标注允许保留，不要求全部替换成最新版本。
- 技术方案：对应 PRD 的链接、版本和涉及端。初版检查完整章节；迭代只检查已出现的模板章节是否重复或乱序，不要求补齐未改动章节。
- 清单与归档：清单版本顺序与 PRD 历史一致；有设计的版本存在同号目录和主方案链接；标为“无技术变更”的版本不应存在版本目录。检查主方案内容，不递归审阅附件正文。
- 模板残留：识别常见项目名、版本号、姓名、日期和模块名占位符，以及已知模板注释、标题提示。`TODO`、`TBD` 和待填写标记输出提醒。
- 本地链接：检查普通行内 Markdown 链接、图片路径是否存在，支持 URL 编码路径及尖括号包裹的含空格路径。按常见 Markdown 标题规则核对锚点，允许中文标题与重复标题后缀。

退出码：`0` 表示未发现明确错误，仍可能有提醒；`1` 表示文档检查发现错误；`2` 表示参数错误或文件读取、解析失败。修复错误后复跑，提醒逐条核对。

## 仍需审阅的内容

脚本按本项目模板的 Markdown 写法检查，不是完整 Markdown 渲染器。围栏代码块和行内代码不参与正文、链接检查；HTML、引用式链接和外部链接会提示人工核对，快捷引用、复杂嵌套链接及非标准表格也需人工检查。锚点未匹配时只提醒，由实际渲染器确认。文件存在不代表内容支持引用结论。

模板残留检查只覆盖已列出的形式；其余引导问题、示意图和模板原文仍须通读清理。脚本不推断“无技术变更”，不判断修改摘要是否准确，也不能证明需求、图表、接口、数据库或代码一致。

审查与验收记录目前允许自由组织，字段完整性和证据含义继续由 AI 审阅。测试是否执行、人工是否验收、Java 规范是否满足，以及中文润色是否保留原意，都需要对应证据。脚本通过不替代这些结论。
