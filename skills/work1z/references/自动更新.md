# 自动更新

本插件的发布来源固定为 [idealzxz/work1z-plugin](https://github.com/idealzxz/work1z-plugin/releases)。使用 Python 3.9 以上版本，无第三方依赖。

## 调用时执行

每次用户发起新的插件任务时，先执行以下步骤。同一次任务中的 Work1z → humanizer-zh 调用、重新读取新版规则及重试不重复检查。

1. 从当前正在读取的 `SKILL.md` 确定实际插件根目录，不使用业务项目的工作目录，也不猜测全局安装位置。
2. 运行该插件根目录下的更新脚本，路径有空格时加引号：

   ```bash
   python3 "/实际插件根目录/scripts/release.py" update
   ```

3. 根据 JSON 输出处理结果：
   - `updated`：文件已更新。重新读取当前 Skill 和本次所需的模板、引用文件，核对根目录 `plugin.json` 版本后再继续任务。不要把宿主缓存中的旧指令当作新版。
   - `up_to_date`、`no_release`、`no_stable_release`：继续当前任务；无 Release 不等于网络失败。
   - `source_checkout`：当前是 Git 开发目录，只报告可用版本，不改写源码或切换分支，继续使用当前版本。
   - `update_busy`：另一个进程正在更新，或上次中断留下锁。等正在运行的更新完成并重新读取文件后再开始任务；无法确认锁的归属时，报告阻塞，不自动删除锁。
   - `error` 或非零退出码：报告原因，不声称已是最新版。下载、校验或本地修改检查失败时继续使用原版本；写入失败但成功回滚时也使用原版本。输出若报告回滚失败，暂停插件任务并保留备份，不能继续使用可能不完整的文件。
4. 宿主要求 `/plugins reload` 或新会话才能重新加载时，提示相应操作，不能声称当前会话已生效。更新脚本只更新当前插件目录中的发布文件，不改宿主的注册数据库、版本目录名称或其他安装副本。管理界面版本可能要通过宿主刷新后才同步。
5. 若宿主没有命令执行权限、Python 或网络访问能力，说明无法自动检查，使用当前版本继续；不自动安装或升级宿主、Python 或额外依赖，也不绕过宿主审批要求。

## 更新范围

仅接受正式 `v主版本.次版本.修订号` Release 中的 `work1z-plugin-vX.Y.Z.zip` 和同名 `.zip.sha256`，不更新到草稿、预发布版本、相同/更低版本或 main 分支。

下载后核对 ZIP SHA-256、包内逐文件清单、路径和三个插件清单的版本。替换前按已安装版本清单核对本地文件；有修改、缺失或新增文件冲突时跳过更新。保留不在旧发布清单中的文件，只移除新版已取消且本地未修改的旧发布文件。写入异常时回滚已替换文件。

Release 安装包自带 `.work1z-release.json`。宿主从 Git 复制的安装缓存若没有该文件，脚本尝试从同版本正式 Release 下载原包取得基线；同版本发布包不存在或与本地文件不一致时，不覆盖。首次启用自动更新应安装包含本机制的正式发布包。

脚本使用 `.work1z-update.lock` 防止多个更新进程同时替换文件。进程被强制终止或机器断电不属于可自动回滚的异常；这时先检查锁和同级 `work1z-update-*` 临时备份目录，恢复或重新安装完整发布包后再使用。
